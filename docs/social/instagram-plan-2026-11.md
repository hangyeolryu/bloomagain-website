## 세 가지 글감

### 1. 갈 곳 — 서울시 문화행사 (목)

목요일인 이유: 주말에 어디 갈지 정하는 날이다. 금요일이면 늦다(2026-10-28 대표 결정).

- 출처: 서울 열린데이터광장 `culturalEventInfo`. 무료 우선, 전시/미술·클래식·국악·전통/역사·교육/체험·무용·연극.
- 기준: **낮에 혼자 가도 되는 것**, 예약 없이 되는 것, 중심부(종로·중구·용산·서초…). 어린이 대상·오디션·공모 제외.
- 카드엔 날짜·장소·값만. 포스터는 쓰지 않는다(주최 저작물). "무료"는 API가 무료라 한 것에만.
- 캡션 끝에 "날짜·시간은 주최 안내를 한 번 더 확인" 한 줄 — 공공데이터는 늦게 바뀐다.
- 고를 때: 같은 종류 6개보다 전시 3 + 음악 2 + 체험 1처럼 섞는다. 한 장에 4줄, 최대 8건.

```bash
node scripts/instagram/seoul-events.mjs --list                  # 점수순 30건
node scripts/instagram/seoul-events.mjs --make free-11-w2 --pick 1,3,4,7,9,12
git add assets/instagram/free-11-w2 && git commit -m "chore(카드): 11월 둘째 주 갈 곳" && git push
node scripts/instagram/publish.mjs --slug free-11-w2 --dry-run   # 확인 후 큐에 넣거나 바로 게시
```

### 3. 스토리

- 피드보다 가볍게, 글자 적게. 9:16(1080×1920), 세트마다 `story.jpg`가 같이 구워진다(`gen-event-cards.cjs`).
- 쓰임 셋: ① 목요일 세트 올린 날 "피드에 올렸어요"(크론 자동) ② 수요일 아침 그 주 자리 리마인드 ③ 자리 전날 "내일 ○○".
- 스토리는 24시간이라 **시각이 중요**하다. 크론은 10:23 예약(GitHub 사정으로 늦어질 수 있음)이니 리마인드는 손으로 아침에.
- 올린 스토리는 `published.json`에 `<slug>#story`로 남는다.

## 만드는 데 드는 손

| 종류 | 손이 가는 곳 | 시간 |
|---|---|---|
| 갈 곳 | `--list` 보고 번호 고르기, 캡션 한 번 읽기 | 10분 |
| 궁금해할 것 | 글 쓰기(캡션·카드 문구), 근거 확인 | 1~2시간 |
| 스토리 | 아침에 명령 한 줄 | 1분 |

화요일 글이 못 나오는 주엔 목요일 갈 곳만 나가도 된다. 반대로는 안 한다 — 갈 곳이 빠지면 "티타는 어디 가는 앱"이라는 인상이 끊긴다.

## 이미지에 대해

지금은 글 카드(딥그린 바탕)만 쓴다. 사진이 들어가면 저장·공유가 늘지만, 남의 사진은 못 쓰고 우리 사진은 자리에서 찍은 것뿐이다.
자리에서 찍은 사진(얼굴 없는 손·찻잔·전시장)을 `scripts/cards/photos/`에 모아 두면 표지 한 장에 깔 수 있다(insight-15 방식).
생성 이미지는 당장 쓰지 않는다 — 45+ 독자에게 "가짜 사진"으로 읽히는 순간 신뢰가 깎인다.
